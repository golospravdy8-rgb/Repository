# PROJECTION MAPPING ANALYSIS
## Physics vs Visual: Пространства и их соответствие

---

## ДИАГНОСТИКА

### Пространство 1: ФИЗИЧЕСКОЕ (SI метры)
```
HOOP_R = 0.45m (на экране 27px)
EFFECTIVE_R = 0.501m (на экране 30.06px с допуском)
ЭТО КРУГ (идеальное баскетбольное кольцо)
```

### Пространство 2: ЭКРАННОЕ (пиксели canvas)
```
VISUAL_RX = 27px (ширина эллипса)
VISUAL_RY = 7.56px (высота эллипса, сплющена = 0.28 × ширина)
ЭТО ЭЛЛИПС (перспективная проекция круга, видимая игроку)
```

### ПРОБЛЕМА: Смешивание двух пространств
```
1. Физика: "контакт на расстоянии 30.06px от центра"
2. Рендер: "эллипс с радиусами 27px (X) × 7.56px (Y)"
3. РЕЗУЛЬТАТ: На Y получается 30.06 - 7.56 = 22.5px ЗАЗОР!
```

### Что видит игрок
При контакте мяча с верхней частью кольца (90°):
- Физический контакт происходит на Y = 337.06px
- Видимый край эллипса находится на Y = 314.56px
- **Мяч отскакивает от НЕВИДИМОГО кольца, которое висит ВЫШЕ нарисованного**
- Или: мяч зависает над видимым краем

## ВЫВОД: Текущая система НЕКОРРЕКТНА

```
✅ Физика: абсолютно верна (SI метры, true circle)
✅ Визуал: абсолютно верен (перспективная проекция)
❌ ИНТЕГРАЦИЯ: отсутствует projection mapping между ними
```

### Почему возникает offset
- Физика работает в одном пространстве (circle, все радиусы = 30.06px)
- Визуал отображает другое пространство (ellipse, сплющена на Y)
- При прямом рендеринге координат мяча вылезает зазор на Y-оси

## ТРИ ВАРИАНТА РЕШЕНИЯ

### ВАРИАНТ A: Ellipse-Space Collision (Масштабирование)

**Идея**: Сжимать Y-координату мяча перед рендером

```javascript
screen_ball_y *= (VISUAL_RY / EFFECTIVE_RIM_RADIUS_PX)
// Сжимает Y в 0.25× раз → мяч "прижимается" к эллипсу
```

**Плюсы:**
- ✅ Простая реализация
- ✅ Мяч визуально касается эллипса
- ✅ Работает при rolling

**Минусы:**
- ❌ Искажает траекторию (выглядит как магнетизм)
- ❌ При отскоке мяч странно "расширяется"

---

### ВАРИАНТ B: Raycast / Normal Projection на Эллипс

**Идея**: Найти точку на эллипсе, соответствующую физическому контакту

```javascript
1. Физика: находит контакт на расстоянии R
2. Вычислить нормаль: n = (contact_x - center) / R
3. Найти точку на эллипсе с этой же нормалью:
   ellipse_x = center_x + VISUAL_RX * n.x
   ellipse_y = center_y + VISUAL_RY * n.y
4. Рендер мяча в ПРОЕЦИРОВАННОЙ позиции
```

**Плюсы:**
- ✅ Математически верно (true projection mapping)
- ✅ Мяч всегда на видимом эллипсе
- ✅ Работает при всех углах контакта

**Минусы:**
- ❌ Рассинхрон: импульс к физической точке, рендер в другой
- ❌ При rolling мяч может "прыгать" между проекциями
- ❌ Сложнее для реализации

---

### ВАРИАНТ C: Linear Y-Mapping (Упрощённая проекция)

**Идея**: Линейное переопроецирование Y-координаты

```javascript
screen_y_corrected = center_y + (physics_y - center_y) * (VISUAL_RY / EFFECTIVE_RIM_RADIUS)
```

**Плюсы:**
- ✅ Близко к Варианту B, но проще
- ✅ Мяч находится на видимом эллипсе
- ✅ Не требует raycast-инга

**Минусы:**
- ❌ Как и B, есть рассинхрон между физикой и рендером

## 🏆 РЕКОМЕНДОВАННЫЙ ПОДХОД: Вариант B+C Hybrid

### Архитектура

**ШАГ 1**: Физика работает как сейчас
- Circle collision detection
- SI units (метры)
- Multi-contact система
- Импульсы применяются к истинным физическим точкам контакта

**ШАГ 2**: Слой projection mapping при рендере
```javascript
function projectBallToEllipse(ballX, ballY, centerX, centerY, ellipseRx, ellipseRy, physicsRadius) {
  // Вектор от центра к мячу
  const dx = ballX - centerX;
  const dy = ballY - centerY;
  
  // Расстояние и нормализованный вектор
  const dist = Math.sqrt(dx*dx + dy*dy);
  if (dist < 0.01) return { x: ballX, y: ballY };
  
  const nx = dx / dist;
  const ny = dy / dist;
  
  // Спроецируем нормаль на эллипс
  const ellipseX = centerX + ellipseRx * nx;
  const ellipseY = centerY + ellipseRy * ny;
  
  return { x: ellipseX, y: ellipseY };
}

// В render loop:
const projectedPos = projectBallToEllipse(
  ball.x, ball.y, 
  HOOP_X_M * SCALE, HOOP_Y_M * SCALE,  // физика в метрах → пиксели
  VISUAL_RX, VISUAL_RY,
  EFFECTIVE_RIM_RADIUS_PX
);
drawBall(projectedPos.x, projectedPos.y, BALL_RADIUS_PX);
```

**ШАГ 3**: Soft projection при rolling
- Для стабильности при multi-contact
- Если dist < rolling_threshold → мягкая интерполяция
- Избегает резких прыжков при переходе между контактными точками

### Результат

✅ Мяч ВИЗУАЛЬНО касается эллипса (то, что видит игрок)
✅ Физика работает с истинным кругом (математически верно)
✅ Ощущение: "мяч касается настоящего, видимого кольца"
✅ Rolling smooth (нет резких скачков)
✅ Стабильность при multi-contact (мяч не прыгает)

## ФИНАЛЬНЫЙ ВЕРДИКТ

### Текущая проблема
**Отсутствие слоя projection mapping между физикой и визуалом**

### Решение на уровне архитектуры
**Добавить функцию projectBallToEllipse(), которая:**
- Берёт физическую позицию мяча
- Вычисляет нормаль (unit vector от центра)
- Возвращает точку на эллипсе с этой же нормалью
- Используется ТОЛЬКО для рендера (физика не трогается!)

### Почему это правильно
1. **Физика остаётся чистой** — работает с истинной геометрией
2. **Визуал правдоподобен** — мяч касается видимого эллипса
3. **Ощущение реалистично** — соответствие между тем, что видит игрок, и где коллизия
4. **Масштабируется** — работает при любых размерах экрана (SCALE factor)
