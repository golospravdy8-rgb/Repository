═══════════════════════════════════════════════════════════════════════════════
  THE PROBLEM
═══════════════════════════════════════════════════════════════════════════════

Hydration Mismatch Warning (Every Page Load):
  "A tree hydrated but some attributes didn't match"

Technical Details:
  Server renders: <html lang="uk">
  Client renders: <html lang="uk" data-yd-content-ready="true">
  
Cause:
  External Yandex tracker script adds data-yd-content-ready attribute
  AFTER React hydration completes
  React detects mismatch and logs console warning

Impact:
  ❌ Console warnings on every page load
  ❌ Polluted DevTools console
  ❌ Makes debugging harder
  ❌ Not breaking but bad UX signal

═══════════════════════════════════════════════════════════════════════════════
  THE FIX (1 LINE CHANGE)
═══════════════════════════════════════════════════════════════════════════════

File: /app/layout.tsx
Line: 21

BEFORE:
  <html lang="uk">

AFTER:
  <html lang="uk" suppressHydrationWarning>

Why It Works:
  ✅ suppressHydrationWarning tells React to skip hydration check on <html>
  ✅ Safe because only affects root element attributes (not content)
  ✅ Industry standard (Google Analytics, Facebook Pixel, Yandex all use this)
  ✅ 2026 best practice recommended by React/Next.js teams
  ✅ No functional impact whatsoever

═══════════════════════════════════════════════════════════════════════════════
  TECHNICAL EXPLANATION
═══════════════════════════════════════════════════════════════════════════════

How suppressHydrationWarning Works:

1. Next.js renders HTML on server:
   <html lang="uk"> ... </html>

2. React hydrates in browser with same HTML

3. External script (Yandex) loads AFTER hydration:
   document.documentElement.setAttribute('data-yd-content-ready', 'true')

4. WITHOUT suppressHydrationWarning:
   React sees HTML changed and logs warning

5. WITH suppressHydrationWarning:
   React skips hydration check on <html> element
   No warning logged
   Everything else validated normally

Why It's Safe:
  ✅ Only suppresses check on <html> tag (visual attributes)
  ✅ Does NOT suppress checks on any child elements
  ✅ Does NOT suppress checks on content/text
  ✅ Industry standard practice since 2021
  ✅ Recommended by Next.js/React documentation
